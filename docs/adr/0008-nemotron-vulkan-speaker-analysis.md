# Nemotron speaker analysis on Windows and Apple Silicon

Issue #17 supersedes the runtime choices in ADRs 0005–0007. All supported builds use NVIDIA Nemotron 3 Diarization Q8 through the native NeMo-Speech.cpp 0.3.0 CLI: Windows CPU, Windows Vulkan/CPU, and macOS Apple Silicon Metal/CPU. The user clarified that limiting CPU benchmarks must not remove CPU product support. Remove the Community Python worker, gated acquisition, sherpa tools and their shipped resources. Whisper recognition and its save boundary stay unchanged; the existing SessionSpeakerWorkflow owns both automatic analysis after recognition and standalone retry.

The native adapter passes one selected mono 16 kHz PCM WAV to `diarize --device cpu|vulkan:0|metal --preset v3-offline --concurrency 1 --format json`. The preset preserves model state across the recording; independent chunk labeling would lose speaker identity. `--offline` is not used because the runtime's full-attention mode has a duration limit. The doctor command must identify the pinned runtime and its CPU backend. Doctor exit 1 with valid capabilities means an accelerator is unavailable, not that CPU inference is broken. The remembered Auto/CPU/GPU preference is independent of Whisper settings and is captured before recognition starts. Auto selects GPU when detected and CPU otherwise, before inference; CPU is always selectable. Explicit GPU requests require a compatible accelerator, and failed GPU inference never silently retries on CPU. Auxiliary work is bounded: one file worker, the upstream four-thread ggml default, OMP/BLAS limits of two, below-normal worker priority and two FFmpeg threads. Phase-only inference progress is intentional: the CLI does not publish a reliable percentage. Cancellation kills the child, awaits close, and removes temporary audio/output before releasing the operation.

The JSON protocol supplies arbitrary speaker labels and overlapping `{start,end,speaker}` segments, without confidence or word timestamps. Validate bounds against the prepared WAV duration and normalize labels into a run-local namespace. Preserve native overlap in `acousticIntervals`; do not claim Community-1 exclusive output. The existing conservative assignment policy requires a clear majority and leaves ambiguous, overlapped or uncovered fragments Unknown. Range and track offsets are applied once by the session workflow. Microphone-only sessions still bypass assets/inference and use a fixed microphone identity. Nemotron exposes automatic count only: UI hides exact count and main rejects an explicit count before downloading or replacing results.

Keep session/transcript version 1 and optional provenance version 1. Native provenance records model and runtime revisions/hashes, the actual CPU/Vulkan/Metal backend and device, preset, audio mode, selected range, assignment policy and acoustic intervals. The legacy provenance type exists only to read saved sessions: older Community-1/sherpa sessions retain their labels and original text without migration or background reanalysis. Corrections, merges, source checks and recognition-generation guards remain in the shared workflow; save replaces the transcript atomically only when analysis is complete and still current.

Reuse the existing component downloader, hash checks, safe ZIP extraction, atomic installation/repair and offline cache. Native libraries live in a private component root with a restricted environment; they never enter Whisper's directory. Pin all three upstream archives in `scripts/nemotron-assets.json`, include upstream Apache-2.0/third-party notices and the model's OpenMDW-1.1 license/card, and verify every packaged file. Upstream 0.3.0 uses narrow Windows path APIs: replace only its embedded asInvoker manifest to enable the UTF-8 active code page, record revision `nemo-speech-0.3.0+utf8.1`, and ship a modification notice. This requires Windows 10 1903 or later. On macOS retain the original binaries and executable permissions, materializing the dylib aliases as regular copies for the existing safe ZIP installer. The app bundles metadata/notices; runtime/model components of approximately 110–124 MB are downloaded on demand. Release acceptance also measures actual paired installers, not only model/archive sizes.

PR CI prepares and verifies each platform archive and exercises the relocated runtime on the target OS with three seconds of synthetic audio. CPU checks are functional smoke tests, not benchmarks. GPU smoke runs on hosts reporting an accelerator, except for the hosted macOS VM: both the repackaged and unmodified upstream archives crash in `AppleParavirtGPUMetalIOGPUFamily` during Metal inference. That job explicitly uses `--cpu-only`; physical Metal qualification is separate. The user verified CPU and Metal on an Apple M1 with macOS 15.7.3, including short and full GPU benchmarks recorded in the acceptance report. Initial Metal capability detection compiles embedded shaders, so the app permits up to three minutes for that cancellable probe. The macOS workflow uses the supported `macos-15` arm64 runner; `macos-14` was retired from GitHub Actions on November 2, 2026 ([runner images](https://github.com/actions/runner-images)).
